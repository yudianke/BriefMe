# BriefMe · 今日简讯

*[English](README.en.md)*

把十几家中外媒体**过去 48 小时**的新闻抓回来，用 AI 分好类、写成摘要，
生成一个可以离线打开的网页。每天一条命令，五分钟看完天下事。
页面右上角可一键切换中文 / English。

```
首页                中国 Top5 / 国际 Top5（同一事件跨媒体合并，只占一个位置）
 ├─ 中国新闻        16 个分类的四列网格，左侧可按媒体筛选
 │   ├─ 国际政治    AI 事件纪要 + 该分类全部报道（标题 / 摘要 / 原文链接）
 │   └─ 按来源      按媒体罗列窗口内**全部**报道，不依赖 AI 分类
 ├─ 国际新闻        英文标题保留原文，下面附中文译题
 └─ 学术期刊        19 本刊按 8 个学科分区 + SCI/SSCI 各五篇精选（独立于上面的新闻流水线）
```

---

## 快速开始

```bash
git clone <你的仓库地址>
cd briefme
pip install -r requirements.txt

cp .env.example .env      # Windows: copy .env.example .env
# 编辑 .env，填入任意一个 AI 服务的 key

python run.py
```

跑完会自动打开生成的网页。之后想再看，双击 `view.bat` 即可（不需要重跑）。

## 原理

新闻部分的流水线分五步，每步的产物都存进本地 SQLite，可以单独重跑
（学术期刊是并行的另一条线，不参与下面这几步，见「学术期刊」一节）：

| 步骤 | 做什么 | 说明 |
|---|---|---|
| **1. 抓取** | 拉 RSS / Google News / 少数站点直接解析 | 只取**标题、一小段摘要、原文链接**，不抓全文；顺带滤掉非新闻页（见下） |
| **2. 翻译** | 英文标题 → 中文译题 | 原标题保持不动，译题另存一列 |
| **3. 分类** | 每篇归 1–2 个分类 | 先看标题；标题看不出来才去读正文开头 |
| **4. 聚合** | 选出每个地区的 Top5 **事件** | 多家媒体报同一件事只算一个事件，来源越多排越前 |
| **5. 汇总 + 渲染** | 每个分类写一段事件纪要，生成静态 HTML | 纯静态页面，不需要服务器 |

几个设计取舍：

- **滚动 48 小时窗口**：数据库长期存历史，但页面和 AI 输入一律只用最近 48 小时，
  以媒体的发布时间为准（不是抓取时间）。用 48 而不是 24，是为了跨时区阅读——
  睡前和醒后各看一次也不会漏掉在你睡着时发布的新闻。
  改窗口只需动 `newsagg/models.py` 的 `WINDOW_HOURS`，
  走 Google News 的源会自动按窗口展开成多条 `when:Nd` 查询（见下）。
- **时间存 UTC**：前端再转成你所在时区显示。
- **摘要预先算好**：不是点进去才现算，所以翻页是瞬间的，AI 花费也可控。
- **纯静态输出**：`output/` 里就是一堆 HTML，可以直接用浏览器打开、
  拷进 U 盘、或者丢到任何静态托管上。
- **入库前过滤非新闻页**：Google News 会把媒体站内的股票行情页
  （`SPYA.N - | Stock Price…`）、栏目与播客页（`CNN Newsroom`）、
  地区标签页（`Virginia - AP News`）也当成文章收进来，实测约占抓取量的 12%。
  这些条目没有内容却会照常参与分类与汇总，所以在写库前就丢掉。
  规则在 `newsagg/fetch.py` 的 `JUNK_TITLE_PATTERNS`，取舍是**宁可漏判也不误杀**，
  且**每条被拦下的都会留档**，可随时复查有没有误伤（见下）。

## 配置 AI 服务

`.env` 里填**任意一个** key 就能跑。已内置 10 家，程序会自动挑第一个配好 key 的：

**中国大陆可直连**：DeepSeek、智谱 GLM、通义千问 Qwen、MiniMax
**境外**：ChatGPT、Gemini、Grok、Claude、Groq

想指定顺序就设 `AI_PROVIDERS=deepseek,qwen`（前面的当主用，失败自动退到后面）。

要加别的服务，在 `newsagg/ai.py` 的 `PROVIDERS` 里加一行即可 —— 只要对方提供
OpenAI 兼容接口，填上地址、环境变量名和模型名就行：

```python
"你的服务": Provider(
    name="你的服务",
    base_url="https://api.example.com/v1",
    api_key_env="YOUR_API_KEY",
    models={"default": "模型名"},
),
```

> 各家的模型名会变，如果报「模型不存在」，去对方文档查一下最新名字改掉即可。

**同一家可以按任务分配不同模型。** `models` 的键就是任务名（`translate` /
`classify` / `summarize` / `events`），缺哪个就回退到 `default`，所以只写
`default` 也能跑——内置的 Groq 就只写了 `default`，全部任务统一用一个模型，
译文风格才一致。想给某个任务换更快或更便宜的模型时，加一个键即可：

```python
models={"default": "openai/gpt-oss-120b", "translate": "llama-3.3-70b-versatile"},
# 注意 extra 是按模型名配的：reasoning_effort 只有 gpt-oss 接受，llama 收到会 400
extra={"openai/gpt-oss-120b": {"reasoning_effort": "low"}},
```

**无论怎么配，你都只需要在 `.env` 填一个 key。**

### 免费额度会用完

免费档除了「每分钟」限流，还有**每天**的 token 上限——Groq 的
`gpt-oss-120b` 约 20 万/天。这个数字**不在响应头里**，只有耗尽时的报错才会提到，
所以程序在本地按天记了一份账：

```bash
python -m newsagg.ai --quota
```

会打印每分钟余量、请求数余量，以及本机今日累计用量。

日额度耗尽时程序不会傻等——它会明确告诉你「当日额度用尽，已用 X/Y，约 N 分钟后
恢复」，跳过该 provider，并把**已完成的部分照常渲染**。这跟每分钟限流是两回事：
后者等几秒就好，前者等到明天才行，硬等只会白白卡住半小时。

一轮完整运行大致消耗多少：抓到 200 篇新稿约 9 万 token，只有几十篇新稿时约 3 万。
额度紧张时可以用 `--no-ai` 只更新标题列表，或用 `--manual` 把 AI 环节交给助手。

**新闻和学术期刊共用同一份日额度，新闻优先。** 论文的译题与精选排在所有新闻步骤
之后跑，捡剩下的额度；首次抓完有约一千篇待译，也按每轮 300 条节流，分几轮补齐
（进度会打印出来）。这个顺序是必需的——反过来先跑论文会把额度吃光，
新闻的分类纪要和 Top5 一段都生成不出来。

额度耗尽时不会空转：任何一步撞到「当日额度用尽」就立即收工并明确告知，
不再对剩下的分类逐个重试，已完成的部分照常渲染。

## 运行模式

```bash
python run.py             # 完整跑一遍（调用 AI）
python run.py --cn-only   # 只抓国内源
python run.py --all       # 跳过联网探测，强制抓全部源
python run.py --no-ai     # 只抓取+渲染，不调用 AI（分类为空，去「按来源」页看）
python run.py --manual    # 不花 API 额度，把 AI 任务交给 Claude Code 之类的助手做
python run.py --en        # 额外生成英文版 AI 内容（见下）
```

### 没有 AI 时文章去哪了

分类是 AI（或 `--manual`）做的，所以 `--no-ai` 抓回来的文章**没有分类**，
进不了任何分类页。为此每个地区都有一个常驻的**按来源页**
（`src-china.html` / `src-world.html`）：按媒体罗列窗口内的全部报道，
取数不经过分类表，因此**窗口内的每一篇都在这里**，跑没跑 AI 都一样。

入口有两个：地区页左侧筛选栏下方的「按来源浏览 →」，以及——当确实有文章
因未分类而没显示时——分类网格上方的一条提示，直接写明有多少篇、并给出链接。
跑完整的 `python run.py` 之后这条提示会自动消失。

> 这一节是从一个真实的 bug 来的：原先只有「一篇都没分类时才按媒体回退」的逻辑，
> 而分类结果长期存在库里，所以跑过一次 AI 之后那个回退永远不再触发。
> 结果是混合状态下未分类的文章在整站任何页面都看不到——实测曾有 1028 篇
> （占窗口的 38%）抓到了却点不到。现在有一条回归测试卡着这一点：
> 窗口内每一篇文章的链接都必须能在 `output/` 的某个页面里找到。

### 复查被过滤掉的条目

抓取时会丢掉媒体站内的非新闻页（行情页、栏目页、标签页）。这类规则最怕误杀真新闻，
所以**每条被拦下的都会连同「因何被拦」一起留档**：

```bash
python -m newsagg.fetch --dropped
```

输出按命中规则分组，**命中数少的排在最前面**——拦下几十条行情页的规则基本不会出错，
只命中一两条的那条才是误杀高发区，一眼就能看到。每条给出媒体、完整标题和原文链接，
可以直接点开核对。

想存成文件慢慢看（Windows 下别用 `>` 重定向，中文会按 cp936 写乱）：

```bash
python -m newsagg.fetch --dropped --out data/dropped-review.txt
```

发现真新闻被误拦，去 `newsagg/fetch.py` 改 `JUNK_TITLE_PATTERNS` 里对应那一条即可；
下一轮抓取它就会正常入库。留档存在数据库的 `dropped_titles` 表，按 URL 去重，
同一个页面天天出现也只占一行并累加次数。

反过来，**新加规则之后，之前已经入库的同类页面还留在库里**，照样会出现在页面上。
用这个命令拿新规则复查全库（默认只预览不删）：

```bash
python -m newsagg.fetch --purge-junk        # 先看清单
python -m newsagg.fetch --purge-junk --yes  # 确认无误后再删
```

删掉的同样会进 `dropped_titles`，还能用 `--dropped` 翻出来。

### 学术期刊

导航第四项。19 本期刊按 8 个学科分区，外加 SCI / SSCI 各五篇 AI 精选。

**数据来自 [Crossref](https://www.crossref.org/) 的公开 API**——出版商自己往那里提交
元数据，一个接口覆盖全部期刊，免费、不需要 key，也就不用逐家爬站、不涉及各家的
robots.txt。缺摘要的条目再用 [OpenAlex](https://openalex.org/) 补一部分。

| | 取值 | 为什么 |
|---|---|---|
| 展示窗口 | 90 天 | 季刊也要有内容：实测《人口学》90 天 28 篇、《管理学会展望》10 篇，新闻那种小时级窗口下会天天空着 |
| 精选取材 | 30 天 | 90 天窗口下榜单几个月不变就失去意义 |
| 抓取频率 | 每 24 小时一次 | 论文不按小时更新 |
| 单刊上限 | 最新 200 篇 | Nature 90 天有近千篇，不截断会把同页的《人口学》28 篇淹掉。学科页按刊标出**实际收录区间**，不笼统写 90 天 |
| 保留期 | 365 天 | 约 9000 行/年，SQLite 毫无压力 |

**它和新闻是两条独立的线。** 论文存在单独的 `papers` 表，不进 `articles`——
翻译、分类、Top5、分类纪要那几步的取数查询都不带地区过滤，论文一旦混进去
就会被整条流水线卷走，既白烧 token 又会污染新闻的分类结果。独立建表是
结构性隔离，现有代码查不到它。

**关于「篇均被引」：那是 OpenAlex 的两年篇均被引，不是 Clarivate 的影响因子（JIF）。**
JIF 是专有数据，本项目拿不到，也不该用别的指标冒充。

**关于五篇精选的可靠性。** 这一步是**选择题**——模型只能从给定候选里挑 5 篇、
每篇写一句不超出标题与摘要的理由，返回的 DOI 必须命中候选集合，
否则整批作废、保留上一版。约七成条目出版商没有提供摘要（Nature、IEEE 三本、
《美国心理学家》等基本为空），这类只能依标题判断，页面上有明确标注。
期刊指标与 DOI 链接由程序直接输出，不经模型，每篇都能点开核对。

加新刊只改 `config/journals.yaml`，填 ISSN、学科和 `sci: true/false` 即可。
注意同一本刊的印刷版与电子版 ISSN 在 Crossref 里是两条独立记录，挑错了会拿到
停更多年的旧数据（《世界政治》就必须用电子版 ISSN）。

### 中文 / English 切换

页面右上角有个切换按钮，点一下整站换语言，选择会记住。分两层：

| | 需要 `--en` 吗 | 说明 |
|---|---|---|
| **界面文字** | 不需要 | 导航、按钮、分类名、媒体名、相对时间，全部内置双语，开箱即用 |
| **AI 生成的内容** | 需要 | 中文报道的英文译题、分类纪要、Top5 事件 |

没跑 `--en` 时切到英文，界面是英文的，AI 那部分回退显示中文——不会空白也不会报错。

`--en` 的做法是**把已生成的中文结果翻译成英文**，而不是用英文再跑一遍 AI。
这样中英两版讲的是同一批事件、同一个排序，切换语言不会看到两份对不上的榜单，
成本也低得多。代价是每次运行的 AI 调用量增加约 40%，所以默认不开。

> **原标题永远不会被替换。** 英文报道的主标题始终是英文原题，中文报道的主标题
> 始终是中文原题；译文只作为副标题出现，显示哪一种取决于当前界面语言。

### `--manual` 模式怎么用

适合手上没有 API 额度、但有 AI 编程助手的情况。**你只需要做两件事：**

**第 1 步 —— 你运行：**

```bash
python run.py --manual
```

抓取照常进行，只是不调用 AI，而是把待办写进 `manual/*.md`
（翻译、分类、Top5、纪要各一个文件，每个都写明了任务要求和输出格式）。

**第 2 步 —— 你对 AI 助手说：**

> 处理 manual 的待办

助手会读那几个 md 文件、把结果写成 `manual/results.json`，**并自己执行回写命令**。
完成后刷新网页即可。

---

<details>
<summary>如果助手只写了 results.json 却没回写（手动兜底）</summary>

自己敲这一条即可：

```bash
python -m newsagg.manual load manual/results.json && python -m newsagg.render
```

它做两件事：把 `results.json` 里的结果读进数据库（`load`），然后重新生成网页（`render`）。
正常流程里这条由助手代劳，你不需要记。

</details>

## 中国大陆使用说明

**不挂代理也能用，只是看不到境外媒体。**

程序启动时会先探测能否访问境外站点（走系统代理，和抓取同一条路）：

- **连得上** → 全部 23 个源正常抓
- **连不上** → 提示一句，自动跳过 17 个境外源，只抓 6 家国内媒体
  （新华社、央视新闻、财新、第一财经、参考消息、南方周末），页面照常生成

这么做是为了避免境外源逐个超时、把一轮抓取拖上几分钟。

**探测走的是和抓取完全相同的网络路径**（httpx + `trust_env`），所以：
环境变量代理、Windows 系统代理（Clash / v2rayN 最常见的模式）、
TUN 全局模式，这三种都能被正确识别，不会误拦。

万一还是误判了（比如代理特别慢、或分流规则把探测域名走了直连），
加 `--all` 跳过探测强制抓全部源：

```bash
python run.py --all
```

反过来，明知没有外网、想省掉探测那几秒，就用 `--cn-only`。

AI 服务同理：DeepSeek / GLM / Qwen / MiniMax 在大陆可直连，用它们就不需要代理。

## 加新的新闻源

编辑 `config/sources.yaml`：

```yaml
  - id: example                 # 唯一标识
    name: 示例日报               # 页面上显示的名字
    name_en: Example Daily      # 英文界面显示的名字（省略则回退用 name）
    region: china               # china 或 world
    lang: zh                    # zh 或 en（en 会自动生成中文译题）
    method: rss                 # rss / gnews / scrape
    feeds:
      - https://example.com/rss.xml
```

- `rss` —— 有 RSS 就优先用
- `gnews` —— RSS 坏了或没有，用 Google News 按 `site:` 查询兜底
- `scrape` —— 前两者都不行，在 `newsagg/scrapers.py` 写个专属解析函数

改完直接跑 `python run.py`，不用改其他代码。

> **gnews 源的 `when:` 会自动展开，照写 `when:1d` 即可。**
> Google News 每条查询最多只返回约 100 条。窗口是 48 小时，直觉上应该把
> `when:1d` 改成 `when:2d`，但实测那样反而**减少**近 24 小时的覆盖——
> 新华社 `when:1d` 拿到 100 条且全在 24h 内，改成 `when:2d` 同样是 100 条上限，
> 却摊到了两天里，24h 内只剩 50 条。
> 所以程序会把一条查询展开成 `when:1d`、`when:2d`……并按 URL 去重合并：
> 近处的密度由 `1d` 保证，远处的尾巴由更大的 `when` 补齐。
> 实测新华社合并后 155 条独有、其中 24h 内 105 条，比单查任何一条都好。
> 改 `WINDOW_HOURS` 时这里会自动跟着变，不需要手动改 yaml。

## 目录结构

```
config/sources.yaml     新闻源清单（加源改这里）
config/journals.yaml    学术期刊清单（加刊改这里）
newsagg/
  fetch.py              抓取 + 境外连通性探测
  scrapers.py           逐站解析（遵守 robots.txt）
  classify.py           分类      translate.py  翻译（外文 -> 中文）
  events.py             Top5 事件  summarize.py  分类纪要
  english.py            --en 模式：把中文结果译成英文
  render.py             生成静态站  ai.py        AI 服务注册表
  manual.py             --manual 模式的导出/回写
  journals.py           学术期刊抓取（Crossref）  paperai.py  论文译题 + 五篇精选
templates/              页面模板 + CSS + 前端脚本（i18n.js 管中英切换）
run.py                  一键入口      view.bat   打开已生成的网页
```

克隆下来时 `data/`、`output/`、`manual/`、`logos/` 都是空的 —— 这些是本地产物，
跑一次就有了。

## 权限与隐私

**不需要管理员权限**，普通用户直接 `python run.py` 就行，不会弹 UAC。

| | 说明 |
|---|---|
| **读取** | 系统代理设置（只读，仅当前用户）；你自己填在 `.env` 里的 API key |
| **写入** | 只写项目目录下的 `data/`、`output/`、`manual/`，不碰系统任何位置 |
| **联网** | 只连新闻站点，以及你在 `.env` 里配置的那家 AI 服务 |

**为什么会读系统代理**：判断"联网要不要走代理"。这一步由 `httpx` / `urllib`
标准库自动完成，本项目代码里没有主动调用；`pip`、`requests` 等常用工具走的是同一条路径。
在 Windows 上它读的是当前用户的 `Internet Settings`（也就是「Internet 选项」里那个代理框），
标准库的实现里只有查询、没有任何写操作。

**不做的事**：不修改系统设置或注册表、不启动子进程、不收集或上传你的本地数据。
抓来的新闻只存在你自己机器上。

**关于杀毒软件**：以源码形式运行的 `.py` 脚本一般不会被拦。如果你自行用
PyInstaller 之类打包成 `.exe`，可能碰上打包器常见的误报 —— 那是打包方式导致的，
和本项目代码无关。

代码不多，介意的话建议直接翻一遍 `newsagg/`，十几个文件，都是纯 Python。
